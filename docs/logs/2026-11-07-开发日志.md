## 2026-11-08 增补 6：Edge 幽灵窗口诊断（28e597d）

**用户反馈**：dev server 运行时，Edge 最小化会被强制还原成最大化；Ctrl+Win+→ 切桌面会看到 about:blank 异常浏览器窗口（桌面 2、桌面 4 各一个）；关掉 dev 后症状消失。

**取证**（qa-snapshot.txt / qa-snapshot2.txt / qa-edge-reg.txt）：
1. 全机**无 chrome.exe 进程**——QA 工具的无头浏览器排除嫌疑（且现也已无残留）
2. 幽灵窗口 = **用户自己的 Edge**：msedge PID 18740 的 MainWindowTitle 为「无标题 - 个人」，即未加载页面的空白窗口
3. 该 Edge 主进程由 `msedge.exe --no-startup-window /prefetch:5` 启动（**后台模式实例**），父进程已退出——这是「启动增强」的拉起方式
4. Edge Preferences 中 startup_boost/background_mode 无显式键 = **默认值开启**

**结论**：幽灵窗口与最小化故障是 Edge 后台模式实例的窗口管理问题（同类用户报告常见于「启动增强」开启时），**与应用代码无关**（应用无 window.open、无 JS 窗口操作）。dev server 的关联性：开着 dev 时 localhost 标签的 HMR WebSocket 持续保活/断线重连，让后台 Edge 长期处于活跃状态，触发该窗口管理缺陷；关掉 dev 后标签变为连接错误页停止重连，症状消失。**触发链未完全定论，但修复方法明确**。

**修复指引（用户侧）**：关闭两个「无标题」窗口 → Edge 设置 → 系统和性能 → 关闭「启动增强」与「关闭 Edge 后继续运行后台扩展和应用」→ 任务栏右键 Edge 彻底退出（确保 msedge 全部结束）→ 重开 Edge 复测最小化。

**工具**：新增 `tools/qa/monitor-chromium.ps1`（记录 Chromium 系进程创建的父进程与命令行），必须纯 ASCII 编写（PS 5.1 读无 BOM UTF-8 中文注释会破坏解析，L10）。

## 2026-11-08 增补 3：平滑动画体系（2fdd16d）

**用户反馈**：系统「辅助功能 → 视觉效果 → 动画效果」关闭后，应用完全没有过渡动画。

**根因**：base.css 的全局 `@media (prefers-reduced-motion: reduce)` 规则把所有 transition/animation 压到 0.01ms。Windows 关动画 → Chrome 上报 reduce → 全站动效失效。这是我自己埋的可访问性规则，设计时未考虑「系统关动画但应用仍想要动效」的场景。

**方案**：动画开关收归应用内（设置 → 视觉 → 动画效果，默认**开启**），落到 `<html>.no-motion` 类；不再读取系统 prefers-reduced-motion。监听挂在 App 根部（否则详情页不引用 settings store 时 watchEffect 不跑——e2e 抓到的第二个 bug）。

**新增动效**：
- 详情页布局列宽过渡 0.34s（`grid-template-columns` 可动画，Chrome 107+）：属性→故事切换时立绘列收窄、面板加宽为平滑移动
- 页签内容由纯淡入改为**滑动**（旧左出 20px / 新右入 20px，mode=out-in）
- 立绘切换淡入淡出 0.24s
- 路由切换 fade（原有）

**验证**（motion.mjs，6/6）：`emulateMediaFeatures` 强制 prefers-reduced-motion: reduce 模拟用户系统环境 → 布局过渡仍在 / 按钮时长 0.18s 级别 / 切换瞬间 tab-body 处于位移中间态 / no-motion 类与 0.01ms 生效。e2e 回归 14/14 通过。
