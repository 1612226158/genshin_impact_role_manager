# 参考界面优化与素材调研 · 2026-11-08

## 判断

现有 Vue / Pinia 架构足以承载当前功能，无须整体重写。当前与游戏参考的主要差距是角色素材类型与背景氛围：游戏使用 3D 模型，仓库使用带底官方海报。不能用背景特效替代角色模型，也不宜裁掉海报文字强行假装透明立绘。

参考：根目录两张微信截图、docs/68d605692055b9f60fbd6d614e37df3a.mp4（93.7s）、docs/4fa8d9782fd49ee8c3fb472e7a79e48e.mp4（318.6s）。视频按 18s / 45s 采样，共查看 12 帧。观察到元素色星海、稀疏漂浮粒子、少量亮星、稳定的三分区和资料阅读器；不采纳无数据支撑的武器养成、圣遗物、命座与语音界面。

## 已落地

- 全屏背景随角色元素切换，背景交叉淡入；离开角色页面回到中性星海。
- 稀疏光点与四角星，部分缓慢上浮。Canvas 最多 180 个点，绘制最多约 30fps，DPR 上限 1.5；设置关闭或标签进入后台时停止动画循环。
- 右侧信息区增加低透明度暗底和细分隔线，保留中央海报与原有布局。
- CharacterRail 负责头像切换与定位：桌面纵向、手机横向，缩放窗口后重新居中；手动滚动时中止定位动画。
- StoryReader 负责故事目录和正文：手动滚动同步当前分节，点击分节时桌面仅滚动正文面板；角色名、称号与按钮保持固定。
- 修正文档残留的 hash 路由说明。

## 后续优先级

1. **素材层**：增加经过确认的透明角色图或名片背景，并允许海报/立绘切换。这比继续堆叠粒子更能改善中心视觉。
2. **数据加载**：当前角色数据构建 chunk 约 1.91 MB（gzip 约 785 KB）。将列表摘要与故事文本分开、故事按角色按需加载，可改善首次加载；需要同时调整数据预处理流水线。
3. **素材浏览**：相册和生日卡增加点击放大预览，便于检查导出前的构图与文字。
4. **存储层**：如果后续需要跨浏览器迁移，增加包含 IndexedDB 图片的完整备份；当前 JSON 仅包含文本与相册索引。

不建议当前就接入完整 3D 展示或全站 Spine。现有页面以资料管理与制作为主，局部交互反馈和可读性收益更高。
