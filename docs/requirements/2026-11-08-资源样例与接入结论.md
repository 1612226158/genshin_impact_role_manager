# 资源样例与接入结论 · 2026-11-08

## 本轮结果

已读取三个仓库的 API 目录和真实文件，下载并检查了三个角色图片样例、两组 Spine 骨骼 JSON、两份 atlas 和可莉纹理。研究样本保存在 `docs/analysis/resources/`（本地分析产物，不入库）。未给正式应用安装运行库或批量替换素材。

## 1. 优先采用：透明角色图与名片

来源：
- [genshin-db 角色图片索引](https://github.com/theBowja/genshin-db/blob/main/src/data/image/characters.json)
- [genshin-db 名片图片索引](https://github.com/theBowja/genshin-db/blob/main/src/data/image/namecards.json)
- [Enka 原神文档：Icons and Images](https://github.com/EnkaNetwork/API-docs/blob/master/docs/gi/api.md#icons-and-images)

实际路径是按类型汇总的 `src/data/image/characters.json`，并非每个角色一个图片 JSON。当前读取到角色图片索引 124 条，122 条包含抽卡立绘文件名，88 条包含官网 cover1；名片索引 300 条。数量随上游变化，不能直接承诺覆盖本项目全部 138 条目。

| 砂糖样例 | 实际下载地址 | 检查结果 | 合适用途 |
|---|---|---|---|
| 抽卡立绘 | [UI_Gacha_AvatarImg_Sucrose.png](https://enka.network/ui/UI_Gacha_AvatarImg_Sucrose.png) | HTTP 200；2048×1024；779,169 bytes；RGBA，alpha 0–255；带人物与自带装饰效果 | 中央舞台、相册、生日卡；横幅比例需单独适配 |
| 官网角色图 | [cover1](https://act-webstatic.hoyoverse.com/upload/contentweb/2022/07/22/448bc697f852e5726717fa2be839eedc_8541949366334435361.png) | HTTP 200；2154×1320；356,061 bytes；调色板 PNG 含透明信息，转 RGBA 后 alpha 0–255 | 透明半身展示，不能当作全身立绘 |
| 名片 | [UI_NameCardPic_Sucrose_P.png](https://enka.network/ui/UI_NameCardPic_Sucrose_P.png) | HTTP 200；420×200；83,703 bytes；几乎不透明 | 小卡、局部背景；不宜直接拉伸成全屏高清背景 |

注意透明判断不能只看模式是否为 RGBA：官网样例为 P 模式，但 `info.transparency` 保存了透明信息，已用实际 alpha 检查。

### 接入方式

1. 在构建期建立 `localId → upstreamId → resourceKey` 映射。砂糖在本项目为 `1055`，上游为 `10000043`，资源键为 `sucrose`，不可用数字 ID 直接覆盖现有数据。
2. 先审计覆盖率，处理旅行者、变体与缺图；只给命中的角色增加资源。
3. 下载后转成本地 WebP，保留 alpha，记录源 URL 和原始尺寸。正式应用继续离线读取本地素材。
4. `images.paintings` 目前按海报渲染，新增透明资源时增加明确的素材类型与构图信息。默认海报、透明半身、横幅抽卡图不能共用同一裁切规则。
5. 第一批以少数角色验证“海报／透明立绘”切换、生日卡和收藏，不改用户已有覆盖层。

## 2. 动画研究：有样例，但需要独立适配

来源：[Genshin Impact Web Material](https://github.com/Dongyifengs/Genshin-Impact-Web-Material)。GitHub 元数据最近推送时间为 2023-07-28。

深入枚举后对上轮推荐作出限定：
- `Genshin-Update-Overview` 默认分支只有 13 个树节点；2.x / 3.x 目录只有 README 和官方活动页链接，不能当作完整动画素材包。
- 1.x 是子模块 [v1.0-v1.6](https://github.com/Dongyifengs/v1.0-v1.6)，固定提交 `7047a2e13cf897bb415fcea659780c0eeb31b0ab`。309 个节点中有 223 PNG、52 JPG、20 MP4，适合研究分层与宣传素材。
- `Spine-Unity` 分支才有具体骨骼示例；其 README 明确说明在 Unity 中复原 `extra` 动画，效果可能有差异。

| 样例 | 分支内路径 | 实测格式 |
|---|---|---|
| 可莉 | `UnitySpineRepo-New/Assets/keli_index/index_keli.*` | skeleton.spine=4.1.00；click / daiji / loop；JSON 251,042 bytes、纹理 PNG 340,621 bytes、atlas 2,710 bytes |
| 安柏 | `UnitySpineRepo-Old/Assets/Example/mengde_p2_anbo/mengde_p2_anbo.*` | skeleton.spine=4.1.08；a / a2b / b；JSON 50,934 bytes、atlas 781 bytes |

两组都有 `extra` 骨骼数据。可莉下载原文件末尾还多出 `')}` 三个字符，直接 `JSON.parse` 会失败；研究时使用 JSON 解码器读取首个完整对象，没有覆盖原始样本。

可莉纹理 atlas 声明 1699×1542，安柏 238×962。没有尝试把 Unity 工程、C# 解析器或未知下载脚本运行到本项目。

### 接入判断

这些是活动插画的骨骼动画，不是游戏内可旋转 3D 模型，也不能为全部角色自动生成待机动作。按 [Spine 官方加载说明](https://esotericsoftware.com/spine-loading-skeleton-data)，需要骨骼、atlas、对应纹理与匹配的运行时。

下一步可建独立、按需加载的实验页：先修复样例副本的文本格式，再验证普通骨骼时间线，最后研究 `extra` 的还原。只有实测渲染、销毁、后台暂停与移动端表现后，才考虑正式接入一个角色的特别展示。当前尚未验证 Web 播放效果。

仓库最近推送时间为 2026-11-05。已检查 [砂糖当前简中 JSON](https://github.com/theBowja/genshin-db/blob/main/src/data/ChineseSimplified/characters/sucrose.json)：

- 仓库 docs/data/characters.md 仍包含旧字段描述，适配应以当前数据和版本化样例为准。

Enka 的角色索引当前为 134 项，名片 ID 索引为 262 项，与 genshin-db 的资源汇总数量不同。不能把不同项目的条目数量等同于完整角色数。需要验证官方 ID、语言、旅行者及皮肤的映射关系。

## 推荐顺序

1. 本地化透明角色图，做海报／立绘切换。
2. 将名片用于生日卡或相册封面。
3. 增加构建期数据适配器和覆盖率报告，避免人工维护多个数据源。
4. 独立研究一组 Spine 样例，再决定是否值得进入正式应用。

## 首页滚动交付

`useSmoothWheel` 仅在角色库挂载，支持目标累加与反向滚动；内部可滚动区域、输入控件、缩放手势、精细触控板小增量保留原生行为，触摸事件不被接管。动效关闭或离开首页时停止缓动。

验证：smooth-scroll.mjs 12/12（含真实滚轮和到达后停止写入 scrollTo），e2e.mjs 14/14，生产构建通过。没有新增依赖。
