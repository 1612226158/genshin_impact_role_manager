## 1. 项目概述

### 1.1 背景

仓库根目录现有原生 `index.html`（3.61 MB，内嵌全量数据）与 `characters.json`（3.69 MB），具备 138 个角色的完整资料与 417 张图片，但功能仅限于**只读浏览**：国度/元素筛选、名称搜索、详情弹窗。此外数据在 JSON 与 HTML 之间存在双份冗余，无构建流程、无版本控制。

本项目的目标不是修补该页面，而是**以同一批数据与素材为基础，重构为可维护、可扩展的 Vue 3 单页应用**，并补齐"管理、生日、相册"三条业务线。

### 1.2 目标

构建一个**纯前端**角色工具应用，具备三类能力：

| 能力域 | 核心诉求 |
|---|---|
| 角色管理 | 浏览、搜索筛选；编辑任意角色字段；新建自定义角色；全部变更本地持久化 |
| 生日工具 | 查询任意日期同日生的角色；按月浏览全部生日；生成并保存生日卡图片 |
| 角色相册 | 收藏角色立绘、上传本地图片、按模板拼图、导出成品 |

### 1.3 硬性约束

1. **技术栈**：Vue 3 + Vite，纯前端，不接任何后端服务、不发任何网络请求。
2. **不污染根目录**：Vue 工程必须位于新建子目录 `genshin-role-tool/` 内。
3. **npm 使用项目级**：所有依赖安装到子目录 `node_modules`，**禁止 `-g` 全局安装**；使用系统 Node，不使用 WorkBuddy 内置 Node。
4. **持久化**：刷新页面、关闭并重开浏览器后，编辑记录、自建角色、相册内容**均不得丢失**。
5. **交付**：完成后提交至 Gitee 源码仓库。

### 1.4 术语表

| 术语 | 含义 |
|---|---|
| 基础数据（base） | 来自 `characters.json` 的 138 个角色，只读，构建期固化 |
| 覆盖层（override） | 用户对基础角色字段的修改，按角色 id 存储 |
| 自建角色（custom） | 用户新建的角色条目，与基础数据同构 |
| 合并视图（merged） | base + override + custom 三者的最终呈现结果 |
| 编辑记录（history） | 每次修改产生的操作日志，可追溯、可撤销 |
| 收藏（collect） | 从角色页把立绘加入相册的动作 |

**可复用的设计语汇（本项目采纳）**

1. 深色星海背景 + 金色细线，不使用阴影模拟材质，改用**低透明度描边 + 发光**
2. 角色以**去边框立绘**直接叠在背景上，底部加光圈伪元素
3. 数值区采用**右对齐 + 细分隔线**的表格化排版，而非卡片
4. 稀有度通过**卡片底色**编码（金/紫），而非文字标注
5. 元素通过**颜色 + 小图标**双通道编码

- **风格定位**：米哈游 UI 是"暗夜靛紫画布 + 金箔边框 + 宝石色元素徽章"的完整体系，刻意对抗西方扁平极简，走"卷轴典籍式"的信息密度路线。排版上是"带幻想气质的衬线展示字体 + 温暖几何体正文"的组合。—— [Curio Design 分析](https://designbycurio.com/zh/learn/mihoyo-genshin-ui-2024)

  | 主金色（菜单/高亮） | `--color-menu` | `#D3BC8E` |
  | 火 Pyro | `--color-pyro` | `#ED4F45` |
  | 水 Hydro | `--color-hydro` | `#4088FF` |

  | 岩 Geo | `--color-geo` | `#CFA726` |

  注：现有 `index.html` 中的元素色为近似值，本次统一替换为上述权威值。
- **生日贺图惯例**：官方在角色生日当天发布贺图 + 游戏内邮件，贺图构图为"角色居中 + 背景虚化 + 节日元素"，配色随角色属性与季节变化。社区习惯把生日贺图做成竖版 4:5 / 1:1 卡片并配一句台词。—— [萌娘百科·原神贺图](https://moegirl.org.cn/原神/贺图)、[Fandom Birthday/Furina](https://genshin-impact.fandom.com/wiki/Birthday/Furina)

  → 原始素材 189 MB 虽未超限，但会让仓库臃肿、clone 缓慢，且含一个 18 MB 单文件。**因此本项目引入图片压缩流水线**（见 7.1）。

### 3.2 字体

- **展示/标题**：`"Noto Serif SC", "Source Han Serif SC", "Songti SC", "STSong", serif`
  —— 对应调研中"幻想气质的衬线展示字体"，中文环境下最接近的内置方案。
- **正文/数值**：`"HarmonyOS Sans SC", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`
- **数字对齐**：所有数值列加 `font-variant-numeric: tabular-nums`，避免列宽跳动。
- 不引入网络字体（纯前端离线可用，且规避授权风险）。

### 3.3 字号阶梯

| 层级 | 字号 / 行高 | 用途 |
|---|---|---|
| Display | 34 / 1.2 | 角色详情页角色名 |
| H1 | 24 / 1.3 | 页面标题 |
| H2 | 18 / 1.4 | 面板小标题 |
| Body | 14 / 1.7 | 正文、故事文本 |
| Caption | 12 / 1.5 | 标签、辅助说明 |
| Micro | 11 / 1.4 | 卡片角标、等级 |

故事正文单独放宽至 15 / 1.95，段落首行不缩进、段间距 12px（对应参考图斜体引语的呼吸感）。

### 3.4 形状与层次

- 圆角：卡片 10px，面板 14px，胶囊 999px
- 描边：1px `--gs-line`；hover 时切 `--gs-line-hi` 并叠加 `box-shadow: 0 0 0 1px rgba(211,188,142,.12), 0 8px 28px rgba(0,0,0,.45)`
- 发光：主按钮与选中态使用 `box-shadow: 0 0 18px rgba(211,188,142,.25)`
- 背景装饰：`Starfield` 组件用 Canvas 绘制 220 个随机星点（半径 0.4–1.6，透明度 0.15–0.7）+ 3 个径向渐变光斑，`prefers-reduced-motion` 下停止动画

### 3.5 动效

| 场景 | 时长 / 曲线 |
|---|---|
| hover 位移 | 180ms `cubic-bezier(.22,.61,.36,1)`，`translateY(-3px)` |
| 面板进出 | 240ms 同上，`opacity` + `translateY(8px)` |
| 详情页切换角色 | 320ms，立绘 `opacity` 交叉淡入 |
| 筛选结果更新 | 仅 opacity，120ms，不做列表重排动画（避免抖动） |

统一遵循 `prefers-reduced-motion: reduce` 降级为瞬时。

## 4. 技术架构

### 4.1 选型

| 关注点 | 选择 | 理由 | 否决方案 |
|---|---|---|---|
| 框架 | Vue 3.5 `script setup` | 用户指定；组合式 API 便于抽存储逻辑 | React / 原生 |
| 构建 | Vite 8（Rolldown 内核） | 用户指定 Vite；实测装到 8.3.6，构建 359ms | Webpack |
| 路由 | `vue-router` 4，**hash 模式** | 纯静态托管（Gitee Pages / 本地双击）无需服务端 rewrite | history 模式（需 404 回退配置） |
| 状态 | `pinia` 3 | 角色/相册/历史三块状态天然分域；devtools 可观测 | 全局 reactive 对象（难调试） |
| 持久化 | `localStorage` + `IndexedDB`（`idb-keyval`） | 文本走 localStorage 便于调试；二进制（上传图、成品图）必须走 IDB，localStorage 5 MB 配额必爆 | 只用 localStorage（会爆配额）；只用 IndexedDB（读文本繁琐） |
| 图像 | 原生 Canvas 2D | 生日卡与拼图是固定版式绘制，无需重型库；零依赖、可精确控制 | html2canvas（需截图 DOM，字体与图片跨域易出问题） |
| 样式 | 原生 CSS + CSS 变量（scoped） | 视觉完全定制，引入 Tailwind 反而增加心智负担 | Tailwind / Element Plus |

### 5.2 分层模型

```
            ┌─────────────────────┐
            │  base  (138 条)      │  只读，构建期打包进 bundle
            └──────────┬──────────┘
                       │ merge by id
            ┌──────────▼──────────┐
            │  overrides  (用户改)  │  localStorage，只存差量
            └──────────┬──────────┘
                       │ append
            ┌──────────▼──────────┐
            │  customs   (用户建)   │  localStorage
            └──────────┬──────────┘
                       ▼
                  merged 视图（Pinia getter，全站唯一数据出口）
```

**合并规则**

1. 以 `id` 为键；override 存在则该角色的字段被逐字段覆盖（浅合并，`images`、`story`、`cv` 单独深合并）。
2. `override.__deleted === true` 表示基础角色被隐藏（墓碑），列表与详情均不出现，可在编辑记录中恢复。
3. 自建角色 id 形如 `c_<timestamp>_<rand4>`，`builtin: false`。
4. 任何角色都可"恢复默认"：删除其 override 记录，并从历史里写一条 `reset` 日志。

### 5.3 存储方案

| 数据 | 位置 | 键/库 | 预估体积 | 理由 |
|---|---|---|---|---|
| overrides | localStorage | `gsr.overrides.v1` | < 200 KB | 纯文本差量，需可直接查看/手改 |
| customs | localStorage | `gsr.customs.v1` | < 300 KB | 同上 |
| history | localStorage | `gsr.history.v1` | 上限 500 条，< 400 KB | 需按序读写 |
| album 元数据 | localStorage | `gsr.album.v1` | < 100 KB | 只存索引与引用 |
| settings | localStorage | `gsr.settings.v1` | < 2 KB | 主题、排序、上次页签 |
| **上传原图 / 成品图** | **IndexedDB** | db `gsr-media`，store `blobs`，key = `mediaId` | 单张 1–8 MB | localStorage 5 MB 配额必然溢出 |
| **收藏的官方立绘** | 不落库 | 直接引用 `assets/` 路径 | 0 | 素材是静态资源，没必要复制一份 |

`useIdb` 封装：`putBlob(id, blob)` / `getBlob(id)` / `delBlob(id)` / `listBlobIds()`；写入后返回 `mediaId`，localStorage 中仅保存 `mediaId` 与元信息。读取时用 `URL.createObjectURL` 并**在组件卸载时 `revokeObjectURL`**，防止内存泄漏。

### 5.4 数据结构定义

```js
// override
{ [id]: { name?, title?, birthday?, ... , __deleted?: true } }

// custom character
{ id, name, title, nation, region_official, affiliation, element, weapon,
  star, birthday, constellation, role, cv: {中,日,英,韩},
  images: { avatar, avatar_hd, paintings: [{label, file}] },
  story: { sections: [{section, text}], full },
  builtin: false, createdAt }

// history entry
{ hid, ts, action, targetId, targetName, changes: [{ field, before, after }] }
// action ∈ 'update' | 'create' | 'delete' | 'reset' | 'restore'

// album item
{ aid, kind, ref, title, characterId, mediaId, createdAt }
// kind ∈ 'official'（引用 assets 路径）| 'upload'（IDB）| 'card'（IDB 成品）
```

### 5.5 版本迁移

所有键带 `.v1` 后缀；启动时读取 `settings.schemaVersion`，若低于当前版本则执行顺序迁移函数表 `migrations = { 1: fn, 2: fn }`，迁移失败则备份原数据到 `gsr.backup.<ts>` 并提示用户，**不静默丢弃**。

### 5.6 基础数据的装载方式

两种可选：`import characters from '@/data/characters.json'`（打进 bundle）或 `fetch('./data/characters.json')`（运行时取静态文件）。

**选择前者（import）**，理由：

- 验收要求"双击 `dist/index.html` 可运行"。`file://` 协议下 `fetch` 本地文件会被 CORS 拦截，而 `import` 打包后是普通 JS 模块，不受影响。
- 138 条数据一次全量装载，无分页需求，运行时零请求。
- 代价是包体增大，故在预处理阶段做两项瘦身（体积均为实测）：

  | 处理 | 字节数 |
  |---|---|
  | 原始 `characters.json`（indent=2 美化格式） | 3,691,425 |
  | `gzip -9` 后 | 836,222 |
  | 去除与 `sections` 重复的 `story.full` 并 minify 后 | 724,840 字符（≈ 2.0 MB UTF-8） |
  | 上述结果再 `gzip -9` | 772,675 |

  即：**构建期 minify + 丢弃冗余 `story.full`（需要时由 `sections` 拼接），源码体积从 3.69 MB 降到约 2.0 MB，gzip 传输约 0.77 MB**。若不瘦身，仅 gzip 也有 0.84 MB，两者差距不大，但源码解析量减少 45%。

素材图片仍走 `public/assets/` 静态路径，通过 `assetUrl()` 统一拼 `import.meta.env.BASE_URL`，确保 base 为 `./` 时子目录部署与本地打开都正确。

素材图片仍走 `public/assets/` 静态路径，通过 `assetUrl()` 统一拼 `import.meta.env.BASE_URL`，确保 base 为 `./` 时子目录部署与本地打开都正确。

## 6. 功能设计

### 6.1 角色库（`/`）

- 布局：桌面端为「筛选侧栏 + 主网格」；**主网格默认 5 列**（对齐参考图 B），随宽度降为 4/3/2 列。
- 卡片构成（自下而上）：稀有度底色渐变 → 立绘/头像 → 左上元素圆形徽章 → 底部半透明标签条（角色名 + 12px 星级）→ 右上角自建/已编辑角标。
- 筛选维度：国度（含"全部"）、元素、星级、武器、来源（官方 / 自建 / 已编辑）。
- 搜索：即时匹配 `name`、`title`、`affiliation`、CV 名，输入防抖 150ms。
- 排序：默认「国度 → 星级降序 → 名称」；可选名称、星级、生日、最近编辑。升降序可切换。
- 顶部统计条：`共 138 条 · 自建 3 · 已修改 12`，点击数字可快速筛选。
- 空态：显示"没有匹配的角色"+ 一键清除全部筛选。

### 6.2 角色详情（`/c/:id`）

严格对齐参考图 A 的骨架：

```
┌────────────────────────────────────────────────┐
│ [元素] 国度 / 角色名            ‹ 上一个 下一个 ›  ✕│
├──────────┬──────────────────────┬──────────────┤

```

- 属性 Tab：国度、所属、元素、武器、星级、生日、命之座、中文 CV，以及四语 CV。
- 背景故事 Tab：按 `sections` 逐节渲染，节标题用金色小标 + 左侧短竖线。
- 相册 Tab：该角色的全部立绘缩略图 + 本项目为该角色保存的相册项。
- 「收藏」把当前立绘写入 album（kind=`official`），按钮态二值切换。
- 无立绘角色（2 条「奇偶」）显示占位插画 + 「官方未提供立绘」。

### 6.3 编辑与新建（`/c/:id/edit`）

- 表单字段与数据结构一一对应；`select` 用于国度/元素/武器/星级，`date` 用两个下拉（月、日）避免年份干扰。
- 立绘字段支持：沿用现有路径 / 替换为相册中上传的图片（写 IDB）。
- 实时校验：名称必填且不可与已有角色重名（重名给出警告但允许保存）；星级 1–5；生日在合法范围内。
- 底部操作：保存 / 取消 / 恢复默认（仅基础角色）。
- 保存时生成 history 条目，字段级 diff（只记改动字段）。
- 未保存离开时拦截（`onBeforeRouteLeave` + 确认弹窗）。

### 6.4 编辑记录（`/history`）

- 时间轴列表，倒序；每条显示时间（`YYYY-MM-DD HH:mm`）、动作类型徽章、角色名、改动摘要（`攻击力：3,107 → 3,200` 这类）。
- 单条撤销：按 `changes` 反向写回（仅当该字段当前值仍等于 `after` 才能安全回滚，否则提示"已被后续修改覆盖"）。
- 筛选：按角色、按动作类型、按时间范围。
- 上限 500 条，超出丢弃最旧；提供"清空记录"（二次确认）。

### 6.5 生日工具（`/birthday`）

**三种使用方式，同一页面三个区**

1. **同日查询**：日期选择器（默认今天）→ 命中列表。规则：
   - 精确匹配 `月-日`；
   - 若查询 2/28 或 2/29，额外命中 2/29 生日角色并标注「闰年日期」；
   - 无命中时显示"这一天没有角色过生日"，并推荐最近的一个生日。
2. **按月浏览**：12 个月签（带当月人数），下方按日期升序分组，每组显示该日角色卡片横排；顶部显示当月总人数与"本月你收藏的角色"。
3. **今日/最近生日**：顶栏常驻一条"距离最近生日还有 N 天"，显示角色头像与日期。

**生成生日卡**：详见 6.6。

### 6.6 生日卡生成

- 模板 2 种（后续可扩展）：
  - `portrait` 1080×1350（4:5）：竖版，适合朋友圈
  - `square` 1080×1080（1:1）
- 图层（自下而上）：
  1. 对角渐变底（以角色元素色为主色，混入 `--gs-bg-0`）
  2. 星点与光斑（复刻参考图背景）
  3. 角色立绘：`contain`，底对齐，水平居中，透明度 1
  4. 顶部金色细线 + 小字「HAPPY BIRTHDAY」
  5. 角色名（衬线，48–64px，字距 4）
  6. 生日日期 + 星座 + 元素圆徽

### 6.7 相册（`/album`）

  - 单张限制 10 MB，超限提示；读取后写入 IDB，仅存 `mediaId`。

  | 主图 + 四小图 | 1600×1000 | 左 1 大 + 右 2×2 |

## 7. 关键实现方案

### 7.1 图片资源处理（重要决策）

**问题**：原始素材 189 MB / 417 文件，含 1 个 18 MB 的单张 PNG。若原样放入仓库并随构建打包，会导致：

- 首屏加载角色卡时拉取数百 KB~数 MB 的 PNG，滚动明显卡顿
- Gitee 仓库体积逼近配额，clone 体验差
- 构建产物 190+ MB

**方案**：构建前跑一次性预处理脚本，产出 WebP 到 `public/assets/`，原图保留在根目录不动。

| 类别 | 原尺寸 | 处理 | 目标 |
|---|---|---|---|
| avatar（icon） | 196×196 | 保持尺寸，WebP q=88 | ≈ 8–12 KB |
| avatar_hd | 686×800 | 保持尺寸，WebP q=85 | ≈ 40–60 KB |
| paintings | 最长边不限（最大 18 MB） | 限制最长边 1400px，WebP q=85 | 单张 ≈ 150–400 KB |

**预估总体积：约 25–40 MB**（从 189 MB 下降约 80%）。脚本同时输出 `manifest.json`（原名 → 新路径），并改写 `characters.json` 中的 `images` 路径，生成 `src/data/characters.json`。

**降级路径**：若 WebP 质量不满足要求，改用 JPEG q=90（无透明通道，立绘均有不透明背景，可接受）；若预处理失败，退回直接复制原图（功能不受影响，仅体积大）。

**验证方式**：脚本跑完后对 3 张代表性图片（恰斯卡 18 MB、砂糖 icon、芙宁娜多立绘）做肉眼比对。

### 7.2 Canvas 绘制与导出

```js
async function loadImage(src) {
  const img = new Image();
  img.crossOrigin = 'anonymous';   // 同源时无副作用，跨源时避免污染画布
  img.decoding = 'async';
  await new Promise((res, rej) => { img.onload = res; img.onerror = rej; img.src = src; });
  return img;
}
```

要点：

1. **画布污染**：所有绘制源必须是同源静态资源或 `blob:` URL。开发态由 Vite dev server 提供，生产态由同域静态托管，均同源，`toBlob` 不会抛 `SecurityError`。若将来改为跨域图床，需给图片服务加 `Access-Control-Allow-Origin`。
2. **清晰度**：画布 `width/height` 直接设为目标像素（1080 等），CSS 尺寸单独设置，不依赖 `devicePixelRatio` 缩放，避免导出尺寸漂移。
3. **文字换行**：中文无空格，需自实现按 `measureText` 逐字累加的断行函数，禁止依赖空格分词。
4. **裁切**：`cover` 用 `drawImage` 的 9 参数版本，计算 `sx/sy/sw/sh`，不用 clip 后缩放（更省性能）。
5. **导出**：`toBlob` 回调在部分浏览器是异步的，封装为 Promise；用 `<a download="原神-角色名-生日卡.png">` + `URL.revokeObjectURL` 触发下载。
6. **字体就绪**：绘制前 `await document.fonts.ready`，否则首帧可能是回退字体。

### 7.3 搜索与筛选性能

138 条数据量极小，**不做索引、不做虚拟滚动**。每次筛选全量 `filter + sort`，实测应在 1 ms 级。仅对输入框做 150ms 防抖，避免连续输入时重复渲染。立绘用 `loading="lazy"` + `decoding="async"`，配合固定宽高比的占位骨架防止布局抖动。

### 7.4 日期处理

- 生日源数据是 `"3月14日"` 字符串，解析为 `{month, day}`；解析失败记为 `null` 并在生日工具中排除。
- 不构造 `Date` 对象做比较（会引入年份与时区陷阱），直接用 `month/day` 数值比较。
- 2/29：生成"闰年生日"标记；非闰年时在按月浏览中排在 2/28 之后并加注。
- "距离最近生日"：以 `month/day` 计算年内天数差，跨年时取 `+365`，不关心具体年份。

### 7.5 空态与降级

| 场景 | 呈现 |
|---|---|
| 图片加载失败 | 显示元素色渐变占位块 + 角色名首字 |
| 无立绘 | 虚线框 + "官方未提供立绘" |
| 无生日数据 | 生日页"未收录生日"分区列出，不出现在月历 |
| localStorage 不可用（隐私模式） | 顶部黄色横幅提示"当前无法保存本地修改"，功能降级为只读 |
| IndexedDB 写入失败（配额） | Toast 提示并说明已删除最旧的上传项 |

## 8. 组件与状态

### 8.1 Store 职责

- `useCharacterStore`：持有 `base / overrides / customs`，对外只暴露 `merged`；`filtered`、`filters`、`sort` 也在此；动作 `saveCharacter`、`createCharacter`、`resetCharacter`、`softDelete`。

- `useAlbumStore`：`items`、`collect`、`addUpload`、`addCard`、`remove`；与 `useIdb` 协作管理 blob。
- `useSettingsStore`：导入导出、清空、schemaVersion 迁移。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 图片压缩后观感下降 | 中 | 先抽 3 张比对；可调 q 值；保留降级到 JPEG/原图 |
| Canvas 导出中文排版溢出 | 中 | 自实现断行 + 字号自适应二分；限制文案字数 |
| localStorage 配额溢出 | 中 | 文本与二进制严格分离；写入失败捕获并提示 |
| 浏览器无痕模式禁用存储 | 低 | 检测可用性，降级只读并横幅提示 |
| 依赖安装失败（网络） | 中 | 已配 npmmirror 镜像（实测 173 ms）；失败时回退官方源 |
| 18 MB 立绘导致浏览器卡顿 | 中 | 压缩至 ≤400 KB；大图在详情页才加载 |
| 提交 Gitee 时仓库超限 | 中 | 压缩后预估 25–40 MB，远低于 500 MB 上限；`.gitignore` 排除 `node_modules` 与原始 zip |
